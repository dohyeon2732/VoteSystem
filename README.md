# 건국대학교 제58대 총학생회 선거 투표율 집계 시스템

선관위원이 휴대폰으로 시점별 누적 투표자수를 입력하면 선거구별·전체 투표율을 자동 집계해 현황판, 공지 문구, CSV로 표출하는 내부용 웹앱입니다. 요구사항은 [docs/요구사항명세.md](docs/요구사항명세.md)를 따릅니다.

## 1차 납품 범위 (이번 버전)

| 영역 | 포함 |
| --- | --- |
| 로그인 | 이름 + 8자리 코드, 세션 2시간, 5회 실패 시 10분 잠금 |
| 입력 | 투표소 자유 선택, 시점 자동 선택, 10분 전부터 허용, 덮어쓰기 경고, 감소 경고, 투표율 미리보기 |
| 확정·승인 | 시점 일괄 확정 / 개별 확정·해제, 확정 후 수정요청 → 총관리자 승인·거절, 관리자 직접 수정 |
| 현황판 | 전체 투표율·50% 게이지·남은 인원, 선거구 순위표(공과대 펼침), 추이 선그래프, 선거구 막대그래프, 전일 동시각 비교, 미입력 경고, 10초 갱신, 다크 테마 |
| 공지 | 시점별 공지 문구 복사, 공지 이미지 PNG 4장(총 투표율 1장 + 선거구 막대 5/5/4) 미리보기·저장, CSV 내보내기 (총관리자만) |
| 설정 | 선거 명칭·기준 투표율, 연장투표·입력 잠금·시간 제한 스위치, 선거구 유권자수, 공통 집계 시각 추가/삭제(기본 12·15·18시), 투표소 운영시간, 전체 입력 초기화 |
| 명부 | 위원 등록(코드 1회 표시), 권한 변경, 코드 재발급, 비활성화, 마지막 총관리자 보호 |
| 로그 | 모든 변경을 누가·언제·이전→이후·사유로 기록 (총관리자만 열람) |

## 3차: 선거인명부 확인·투표용지 불출 (명세 v1.1 15절)

| 영역 | 포함 |
| --- | --- |
| 명부 확인 (위원 휴대폰) | 학번 조회 → 신분증 확인 → 투표용지 불출. 이미 투표·다른 선거구·명부 없음 안내. 휴학생은 "재학생 명단 편입"으로 표시. 본인 체크 5분 내 취소 |
| 꼬리표 마감 | 마감 버튼을 누른 순간이 구간 경계. 꼬리표 수 = 체크 인원일 때만 저장. 누락분 추가, 총관리자 조정. 70분 넘게 마감이 없으면 경고 |
| 집계 연동 | 대조가 끝난 값이 시점 ±10분 안이면 그 시점 입력값으로 자동 반영. 대조 미완료 시점은 확정·공지 불가. 현황판에 실시간·대조 인원 함께 표시 |
| 선거인명부 (총관리자) | 엑셀/CSV 업로드(열 지정·단과대 연결·검증), 기본 유권자수 = 정회원 수 자동 계산, 개별 추가·정정, 체크 취소, 백업·복원, 장애 기록 시트 가져오기, 체크 기록 초기화, 보유기간·파기, 가짜 명부 23,000명 |
| 근무표 | 엑셀/CSV 업로드·화면 편집. 위원은 근무 시간(±15분)에 근무 투표소 선거구 명부만 조회 |
| 개인정보 | 이름·학과 AES-256-GCM 암호화, 학번은 HMAC 해시로만 저장, 첫 사용 시 서약, 모든 조회 접근 로그, 목록·다운로드 기능 없음 |

위원 메뉴의 손 입력은 명부가 등록되면 사라지고 총관리자 "비상 입력"으로만 남습니다.

## 로컬 실행

Node 22.13 이상 (이 Mac은 25.6). Supabase 없이 `data/vote.sqlite` 파일에 저장됩니다.

```bash
npm install
```

```bash
npm run dev
```

브라우저에서 http://localhost:5173 을 엽니다. 최초 총관리자는 `.env`가 없으면 **이름 `관리자` / 코드 `ADMIN123`** 입니다. 실제 운영 전에 `.env`를 만들어 바꾸세요 (`.env.example` 참고).

처음 켜면 선거구 14개·투표소 16개·시점이 자동으로 들어갑니다. 유권자수는 0이므로 **설정 → 선거구 기본 유권자수**에 입력하세요.

> 리허설: 설정에서 **"시점 시간 제한 적용"을 끄면** 선거일 전에도 어느 시점이든 입력할 수 있습니다. 리허설이 끝나면 **전체 입력 초기화**로 입력·수정요청·로그를 지우고, 시간 제한을 다시 켜세요.

## 운영 흐름 (선거인명부 운영 시)

1. 총관리자가 **위원**에서 위원을 등록하고, **근무표**에서 근무표를 올립니다.
2. **선거인명부**에서 정회원 파일과 준회원 파일을 각각 올립니다 (리허설은 "가짜 명부 23,000명 만들기").
3. 위원은 근무 시간에 **명부 확인**을 열고(첫 사용 때 서약) 학번을 조회해 투표용지를 불출합니다.
4. 약 1시간마다, 그리고 공지 시각(12:00·15:00·18:00·22:30)에는 꼭 **꼬리표 마감**을 누르고 꼬리표 수를 입력합니다.
5. 총관리자는 **대조**에서 투표소별 상태를 보고, 맞출 수 없는 구간만 조정합니다. 마감 때마다 **선거인명부 → 백업 CSV**를 받아 둡니다.
6. 모든 투표소의 대조가 끝난 시점을 **확정·승인**에서 확정하고 **공지**를 냅니다.
7. 리허설 후에는 **선거인명부 → 체크 기록 초기화**, 실제 명부로 교체, 실제 근무표로 교체합니다.
8. 결과 공고일과 보유일수를 입력해 두고, 기간이 지나면 **파기**합니다.

## 운영 흐름 (명부 없이 손 입력만 쓸 때)

1. 총관리자가 **명부**에서 위원을 등록하고 코드를 전달합니다 (코드는 한 번만 표시).
2. 위원은 **입력**에서 투표소를 누르고 누적 투표자수와 휴학생 수를 입력합니다. 시점은 현재 시각 기준으로 자동 선택됩니다.
3. 공지 직전에 총관리자가 **확정·승인**에서 시점을 일괄 확정합니다. 확정 후 고치려면 위원은 수정요청을 보내고 총관리자가 승인합니다.
4. **공지**에서 문구를 복사해 올리고, 선거 후 CSV를 내려받습니다.
5. 연장투표가 결정되면 **설정 → 연장투표 활성화**를 켭니다.

## 계산 규칙 요약

- 유권자수 = 기본 유권자수 + 휴학생 투표자수, 투표율 = 누적 투표자수 ÷ 유권자수 (소수 둘째 자리 고정)
- 특정 시점의 전체값은 각 투표소의 그 시각 기준 최신 누적값을 합산합니다. 미입력 투표소는 직전 값을 이어 쓰고 "미입력"으로 표시합니다.
- 공과대학3(법학관)은 야간 전용(18:30~22:30)이라 20:30, 22:30 시점만 있습니다.

## 배포 (Supabase + Vercel, 무료)

로컬에서 검증한 뒤 진행합니다. 두 서비스 모두 GitHub 계정으로 가입할 수 있습니다.

1. **Supabase** (https://supabase.com) → New project. 프로젝트가 만들어지면 **SQL Editor**에서 `server/db/schema.sql` 내용을 붙여 넣고 Run.
2. Supabase **Project Settings → API**에서 `Project URL`과 `service_role` 키를 복사합니다. (anon 키가 아닙니다. service_role 키는 절대 프론트나 공개 저장소에 넣지 마세요.)
3. 이 폴더를 GitHub 저장소에 올립니다 (`.env`, `data/`는 `.gitignore`로 제외됨).
4. **Vercel** (https://vercel.com) → Add New Project → 저장소 선택. Framework는 Vite로 자동 인식됩니다.
5. Vercel 프로젝트 **Settings → Environment Variables**에 아래를 등록하고 Deploy:

| 변수 | 값 |
| --- | --- |
| `SUPABASE_URL` | 2번의 Project URL |
| `SUPABASE_SERVICE_KEY` | 2번의 service_role 키 |
| `SESSION_SECRET` | 긴 임의 문자열 (예: `openssl rand -hex 32` 결과) |
| `ADMIN_NAME` | 최초 총관리자 이름 |
| `ADMIN_CODE` | 최초 총관리자 코드 (영숫자 8자 이상 권장) |
| `VOTER_ENC_KEY` | 선거인명부 이름·학과 암호화 키. `openssl rand -base64 32` 결과 |
| `VOTER_HMAC_KEY` | 학번 해시 키. 위와 다른 값으로 `openssl rand -base64 32` |

> 두 명부 키를 잃으면 명부를 다시 올려야 하고 백업 복원이 안 됩니다. 위원장·간사가 오프라인 사본을 1부씩 보관하고, 파기 후에는 지웁니다.

6. 배포 주소로 접속해 총관리자로 로그인 → 설정·명부 입력 → 리허설 → 초기화.
7. Supabase 프로젝트 리전이 **서울(Northeast Asia (Seoul), ap-northeast-2)** 인지 Project Settings → General에서 확인하세요. Vercel 함수는 `vercel.json`의 `regions: ["icn1"]`로 서울에서 실행됩니다.
8. Supabase 무료 프로젝트는 **7일 미사용 시 일시정지**됩니다. 선거 전날 대시보드에 들어가 Resume 되어 있는지 확인하세요.

배포 환경에서는 쿠키에 `Secure`가 붙으므로 HTTPS(Vercel 기본)에서만 로그인이 유지됩니다.

### 이미 배포한 프로젝트를 v1.1(선거인명부)로 올릴 때

1. Supabase **SQL Editor**에서 `server/db/schema.sql` 전체를 다시 붙여 넣고 Run (여러 번 실행해도 안전, 기존 데이터 유지).
2. Vercel 환경변수에 `VOTER_ENC_KEY`, `VOTER_HMAC_KEY`를 추가하고 GitHub에 push해 다시 배포.
3. 총관리자로 로그인 → 선거인명부 화면 상단에 키 경고가 없는지 확인.

## 보안 메모

- 코드는 scrypt 해시로만 저장되고 원문은 발급 시 한 번만 표시됩니다.
- 모든 쓰기와 권한 검사는 서버에서 하며 브라우저는 DB에 직접 접근하지 않습니다.
- 변경 로그는 삭제 API가 없습니다 (테스트 초기화만 예외).
- 선거인명부: 이름·학과는 암호화, 학번은 해시로만 저장됩니다. 체크 기록은 DB 트리거로 수정·삭제가 막혀 있고(체크 기록 초기화·파기 함수만 예외), DB 함수는 service_role만 호출할 수 있습니다.
- 명부 조회는 근무표 기준으로 서버가 매번 검사하고, 모든 조회가 접근 로그에 남습니다 (학번은 해시 앞 8자리만).
