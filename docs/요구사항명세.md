# 제58대 총학생회 선거 투표율 집계 시스템 요구사항 명세서

2026-10-30 · 2026-11-05 개정 · 중앙선거관리위원회

## 1. 문서 개요

이 문서는 건국대학교 중앙선거관리위원회가 2026년 11월 23일부터 치르는 제58대 총학생회 선거의 투표율 집계 시스템을 정의한다. 투표소 위원이 휴대폰으로 선거인명부에서 학번을 조회해 투표 여부를 체크하고 총학생회 투표용지를 불출하면, 시스템이 체크 인원을 1시간 단위 꼬리표 대조로 검증한 뒤 선거구별·전체 투표율을 자동 집계하고 현황판·공지 문구·공지 이미지·CSV로 표출한다. 선거인명부 기능은 15절에 정의하며, 15절이 앞 절과 충돌하면 15절을 따른다.

## 2. 용어 정의

문서 전체에서 아래 용어를 같은 뜻으로 쓴다.

| 용어 | 정의 |
| --- | --- |
| 선거구 | 유권자수를 보유하고 투표율을 표출하는 단위. 단과대학 14개 |
| 투표소 | 실제 투표가 이루어지고 입력이 일어나는 단위. 16개. 공과대학은 투표소 3곳이 한 선거구에 속함 |
| 집계 시점 | 누적 투표자수를 입력하는 기준 시각. 날짜 + 시각으로 식별 (예: 11/23 13:00) |
| 기본 유권자수 | 선거구별 재학생 유권자 수. 휴학생 제외. 선거인명부가 등록되면 그 선거구 정회원 수로 자동 계산 |
| 누적 투표자수 | 해당 시점까지 그 투표소에서 투표한 사람의 총수. 휴학생 포함 |
| 휴학생 투표자수 | 누적 투표자수 중 휴학생의 수 (누적). 유권자수 분모에 더해짐 |
| 유권자수 | 기본 유권자수 + 휴학생 투표자수. 투표율의 분모 |
| 증가분 | 직전 시점 대비 누적 투표자수 차이. 시스템이 자동 산출 |
| 확정 | 총관리자가 입력값을 잠그는 행위. 확정 후에는 수정요청을 통해서만 변경 |
| 수정요청 | 확정된 값에 대해 선관위원이 새 값과 사유를 제출하고 총관리자 승인을 기다리는 건 |
| 개표 가능 | 전체 투표율이 기준(50%) 이상인 상태 |
| 총관리자 | 설정·명부·확정·승인·잠금 권한을 가진 사용자. 복수 가능 |
| 선관위원 | 입력·열람·산출물 생성 권한을 가진 사용자 |
| 접근 코드 | 사용자별로 발급되는 8자리 영숫자. 이름과 함께 로그인에 사용 |
| 위원 명부 | 시스템 사용자(총관리자·선관위원) 목록. 화면 S-07. 선거인명부와 다름 |
| 선거인명부 | 총학생회 선거 유권자 목록. 정회원 + 준회원. 단과대학 선거의 명부는 포함하지 않음 |
| 정회원 / 준회원 | 정회원 = 재학생(기본 유권자수에 포함), 준회원 = 휴학생(투표하면 유권자수 분모에 더해짐) |
| 체크 | 투표소 위원이 학번으로 선거인을 조회해 투표함으로 기록하는 행위. 투표용지 1장 불출과 같음 |
| 꼬리표 | 투표용지를 불출할 때 떼어 투표소에 보관하는 쪽지. 불출 매수의 실물 증거 |
| 마감(꼬리표 대조) | 투표소에서 위원이 마감 버튼을 누른 순간을 경계로, 직전 마감 이후의 체크 인원과 꼬리표 수를 맞춰 보는 절차. 약 1시간마다 |
| 대조 구간 | 직전 마감 시각부터 이번 마감 시각까지. 첫 구간은 투표소 개장부터 |
| 인정 인원 | 마감에서 공식 인원으로 확정된 수. 일치하면 체크 인원과 같고, 총관리자 조정이 있으면 조정값이 반영된 수 |
| 근무표 | 위원별 근무 날짜·시간·투표소. 선거인명부 조회 권한의 근거 |

## 4. 선거 일정과 집계 시점

투표는 2026년 11월 23일(월)부터 25일(수)까지 3일간 진행하고, 연장 시 11월 26일(목) 하루를 추가한다. 주간 투표소는 하루 3개 시점(12:00, 15:00, 18:00 마감), 야간 투표소(공과대학3)는 마감 1개 시점에 입력한다. 집계 시각은 총관리자가 설정에서 추가·삭제할 수 있다.

| 구분 | 내용 |
| --- | --- |
| 투표일 | 2026-11-23(월), 11-24(화), 11-25(수) |
| 연장투표일 | 2026-11-26(목). 총관리자가 "연장투표 활성화" 토글을 켜면 전체 선거구에 동시 적용. 시간표는 평일과 동일이며 설정에서 따로 지정 가능 |
| 주간 투표소 (15곳) 집계 시점 | 12:00, 15:00, 18:00(마감). 3시간 간격 |
| 야간 투표소 (공과대학3 법학관) | 운영 18:30\~22:30, 집계 시점 22:30(마감). 중간 시점이 필요하면 집계 시각(예: 21:00)을 추가 |
| 전체 시점 축 (현황판·공지 기준) | 12:00, 15:00, 18:00, 22:30 (하루 4개) |
| 시점 생성 규칙 | 전 투표소 공통 "집계 시각" 목록(기본 12:00, 15:00) 중 투표소 운영시간 안에 드는 시각 + 그 투표소의 마감 시각. 총관리자가 설정에서 집계 시각을 추가·삭제하면 모든 투표소·날짜에 즉시 반영. 없어질 시점에 입력값이 있으면 변경을 막음 |
| 입력 허용 시간 | 각 시점의 10분 전부터. 미래 시점은 입력 차단 |
| 하루 최종 전체값 | 22:30 시점 (야간 투표소 마감 포함) |

시점은 투표소별로 설정하되 현황판은 모든 투표소의 시점을 합친 축으로 표시한다. 야간 투표소가 없는 18:00 시점의 전체값은 6절의 합산 규칙을 따른다.

## 6. 계산 규칙

투표율은 누적 투표자수를 "기본 유권자수 + 휴학생 투표자수"로 나눈 값이며, 전체 투표율이 50% 이상이면 개표 가능이다. 모든 계산은 시스템이 자동으로 하고, 입력자는 두 숫자만 넣는다.

**입력값 (투표소 × 시점마다)**

1. 누적 투표자수 (휴학생 포함, 0 이상 정수)
2. 그중 휴학생 투표자수 (누적, 0 이상 정수, 누적 투표자수 이하)

**계산식**

```latex
\text{유권자수} = \text{기본 유권자수} + \text{휴학생 투표자수}
```

```latex
\text{투표율} = \frac{\text{누적 투표자수}}{\text{유권자수}} \times 100
```

| 규칙 | 내용 |
| --- | --- |
| 투표소 값의 출처 | 선거인명부 체크에서 꼬리표 대조를 마친 인정 인원(누적)과 그중 준회원 수. 사람이 숫자를 입력하지 않음 (15.6). 손 입력은 총관리자 비상용 |
| 선거구 값 | 소속 투표소의 누적 투표자수와 휴학생 수를 각각 합산. 공과대학은 3곳 합산 |
| 전체 값 (특정 시점) | 그 시각 기준 각 투표소의 최신 누적값을 합산. 미입력 투표소는 직전 시점 값을 이어서 쓰고, 개장 전이면 0 |
| 미입력 표시 | 해당 칸은 "미입력"으로 빨간 표시, 전체값 옆에 "n개 투표소 미입력" 경고 |
| 증가분 | 현재 시점 누적 - 직전 시점 누적. 하루 첫 시점은 전날 마지막 시점 대비 |
| 개표 가능 기준 | 전체 투표율 50% 이상 (설정값). 달성 여부와 "개표 가능까지 n명"을 표시. n = 올림(유권자수 × 0.5) - 누적 투표자수 |
| 감소 경고 | 누적값이 직전 시점보다 작으면 입력 시 경고. 저장은 허용 |
| 표기 | 투표율은 소수점 둘째 자리까지 고정 (51.20%), 인원은 천 단위 쉼표 (1,412명). 현황판·공지·이미지·CSV 공통 |
| 유권자수 수정 | 선거인명부가 등록되면 기본 유권자수 = 선거구 정회원 수로 자동 계산하고 손 수정은 막는다. 명부 정정 시 모든 시점의 투표율을 즉시 재계산 |

**계산 예시**

경영대학 기본 유권자수가 1,400명이고 15:00 시점에 누적 투표자수 471명, 그중 휴학생 12명이면 유권자수는 1,412명, 투표율은 471 ÷ 1,412 = 33.36%다. 12:00 시점 누적이 300명이었다면 증가분은 171명이다.

## 7. 기능 요구사항

기능은 로그인, 설정, 입력, 확정·수정요청, 현황판, 산출물, 운영 일곱 영역으로 나뉘고 모두 1차 납품 범위다 (공지 이미지 FR-60만 2차). 선거인명부 기능(FR-80\~FR-99)은 15절에 있고 3차 납품이다. v1.1에서 FR-20\~FR-24 손 입력은 총관리자 비상용으로 바뀌었다. 우선순위 필수는 선거 당일 없으면 운영이 불가능한 기능이다.

## 10. 데이터 모델

데이터는 8개 테이블로 구성하며, 입력값은 "투표소 × 시점"당 한 행이고 변경은 로그 테이블에 추가만 한다.

| 테이블 | 필드 | 설명 |
| --- | --- | --- |
| election (선거 설정) | id, name, threshold\_pct, extension\_enabled, input\_locked | 단일 행. 기준 투표율 기본 50 |
| election\_day (투표일) | id, date, is\_extension, sort | 11-23, 11-24, 11-25, 11-26(연장) |
| district (선거구) | id, name, sort, base\_voters | 기본 유권자수는 여기에만 저장 |
| station (투표소) | id, district\_id, name, sort, open\_time, close\_time | 야간 투표소는 18:30 / 22:30 |
| slot (집계 시점) | id, station\_id, day\_id, time, is\_close | 투표소별로 생성. 자동 생성 후 수정 가능 |
| member (위원) | id, name, role, code\_hash, active, created\_at, last\_login\_at | role = admin 또는 member. 코드 원문은 저장하지 않음 |
| entry (입력값) | station\_id, slot\_id, cumulative, leave\_cumulative, entered\_by, entered\_at, confirmed, confirmed\_by, confirmed\_at | 투표소×시점 유일 |
| change\_request (수정요청) | id, entry 키, new\_cumulative, new\_leave\_cumulative, reason, requested\_by, requested\_at, status, decided\_by, decided\_at, decision\_note | status = pending / approved / rejected |
| audit\_log (변경 로그) | id, at, actor\_id, actor\_name, action, station\_id, slot\_id, before, after, note | 추가만 가능. action 예: entry.create, entry.overwrite, entry.confirm, request.approve, voters.update |

로그인 세션은 서버 서명 토큰(2시간 만료)으로 처리하고, 토큰에 코드 발급 버전을 넣어 재발급 시 즉시 무효화한다.

## 11. 산출물 규격

산출물은 공지 문구, 공지 이미지 4장, CSV 세 가지이며 숫자 표기는 6절 규칙을 따른다.

**공지 문구 (FR-50)**

시점을 고르면 아래 형식으로 생성하고 복사 버튼을 제공한다. 선거구 줄은 5절 순서로 14줄이다.

```markdown
[건국대학교 제58대 총학생회 선거 투표율 현황]
2026.11.23.(월) 13:00 기준
전체 투표율 23.40% (3,866명 / 16,521명)
개표 가능까지 4,395명

건축대학 35.39% (132명 / 373명)
경영대학 33.36% (471명 / 1,412명)
...
```

**공지 이미지 (FR-60, 2차)**

| 항목 | 규격 |
| --- | --- |
| 장수 | 시점당 4장: 총 투표율 카드 1장 + 선거구 막대 카드 3장 (5 / 5 / 4 선거구, 총학생회 행 없음) |
| 크기 | 1080 × 1350 px (4:5), PNG, 2배 해상도 렌더링 후 축소 저장 |
| 디자인 원본 | design 폴더의 SVG 2종 (일러스트레이터 내보내기). 틀·로고·막대·글자 좌표와 크기를 그대로 재현 |
| 폰트 | Pretendard (무료). 원본의 Interop Regular/Medium/SemiBold/Bold를 같은 굵기로 대체 |
| 막대 | 채움색 #094152, 길이 = 투표율 비례, 모든 막대에 50% 위치 빨간 기준선(#e7211a). 기준선 위치는 설정값과 연동 |
| 제목 줄 | "건국대학교 제58대 총학생회 선거 투표율" / "2026.11.23.(월) 13:00 기준" (요일 자동) |
| 수치 줄 | 막대 카드: "132명/373명 (35.39%)". 총 투표율 카드: 큰 글씨 "46.84%" + "7,738명 / 16,521명" |
| 저장 | "4장 한 번에 저장" + 개별 저장. 파일명 투표율\_11-23\_13-00\_1.png \~ \_4.png |

**CSV (FR-51)**

전체 기간을 한 파일로 내보내며, UTF-8 BOM을 붙여 엑셀에서 바로 열린다. 한 행은 투표소 × 시점이다.

```csv
날짜,시각,선거구,투표소,기본유권자수,휴학생투표자수,유권자수,누적투표자수,증가분,투표율,입력자,입력시각,확정여부
2026-11-23,13:00,경영대학,경영대학,1400,12,1412,471,171,33.36,홍길동,2026-11-23 13:02,Y
```

## 12. 기술 구성과 배포

프론트는 React + TypeScript, 서버는 Vercel 서버리스 API, 데이터베이스는 Supabase Postgres를 쓰며 모두 무료 플랜이다. 모든 쓰기와 코드 검증은 서버 API를 거치므로 브라우저는 DB에 직접 접근하지 않는다.

| 계층 | 선택 | 이유 |
| --- | --- | --- |
| 프론트엔드 | React 18 + TypeScript, Vite | 요청 사항. 빌드가 가볍고 Vercel 배포가 자동 |
| 서버 | Vercel 서버리스 함수 (TypeScript) | 서버 관리 없이 무료. 코드 검증·권한·쓰기 처리 |
| 데이터베이스 | Supabase Postgres (무료) | 관계형이라 집계 쿼리가 쉬움. 서비스 키는 서버 환경변수에만 저장 |
| 로컬 개발 모드 | 저장소 어댑터로 로컬 파일(SQLite) 사용 | Supabase 없이 노트북에서 전체 기능 검증 |
| 실시간 갱신 | 10초 간격 폴링 | 사용자 30명 규모에서 충분하고 구조가 단순 |
| 차트 | 경량 차트 라이브러리 (Recharts) | 선그래프·막대그래프 2종만 필요 |
| 이미지 생성 | 브라우저 Canvas 렌더링 → PNG | 서버 비용 없음. SVG 좌표를 그대로 사용 |
| 폰트 | Pretendard (OFL, CDN 또는 내장) | 무료이고 웹 임베딩 허용 |

**배포 절차**

1. 발주자가 Supabase 계정을 만들고 프로젝트 1개를 생성 (GitHub·Vercel 계정은 보유)
2. 개발 담당이 제공한 스키마 SQL을 Supabase SQL 편집기에서 실행
3. GitHub 저장소를 Vercel에 연결하고 환경변수(Supabase URL, 서비스 키, 세션 비밀키, 초기 총관리자 이름·코드) 등록
4. 배포 주소로 초기 총관리자 로그인 후 설정·명부 입력
5. 선거 전날 접속해 Supabase 프로젝트가 깨어 있는지 확인

배포 가이드는 화면 단위 절차로 별도 문서로 제공한다.

## 13. 납품 단계와 수용 기준

1차는 공지 이미지를 제외한 전체 기능을 로컬 모드로 검증해 납품하고, 2차는 이미지 생성과 배포를 마무리한다. 선거 전 리허설은 2차 납품 후 실제 배포 환경에서 한다.

| 단계 | 범위 | 수용 기준 |
| --- | --- | --- |
| 1차 | FR-01\~FR-51, FR-70\~FR-72 (이미지 제외) · 로컬 모드 · 사용 설명서 | 16개 투표소의 하루치 입력을 넣었을 때 현황판·공지 문구·CSV의 투표율이 6절 계산식과 일치. 확정 후 수정요청→승인 흐름이 로그에 남음. 선관위원 코드로 관리 화면 접근 불가 |
| 2차 | FR-60 공지 이미지 · Supabase/Vercel 배포 가이드 · 세부 다듬기 | 생성된 PNG 4장을 원본 예시 이미지와 겹쳌을 때 글자·막대 위치가 일치. 휴대폰 2대에서 동시 입력해도 충돌 없음 |
| 3차 | 선거인명부 확인·불출·꼬리표 대조·근무표 (15절, FR-80\~FR-99) · 로컬 모드 검증 후 기존 배포에 반영 · Supabase 스키마 추가 SQL | 15.11의 수용 기준 |
| 리허설 | 위원 전원 모의 입력 후 초기화 | 모의 입력이 초기화 후 현황판·로그에 남지 않고 설정·명부는 유지. 3차 이후에는 가짜 선거인명부 23,000명으로 체크·마감까지 진행 후 FR-97로 초기화 |

**공통 수용 기준**

- 누적값이 직전 시점보다 작은 입력은 경고가 뜨고, 확인 후에만 저장된다
- 18:00 시점의 전체값에 공과대학3의 전날 마감값이 포함되고, 22:30 시점에 당일값으로 바뀜다
- 휴학생 1명을 추가하면 분자와 분모가 함께 1씩 늘어난다
- 세션 2시간 경과 후 저장 시도는 로그인 화면으로 돌아가고 입력값은 유실되지 않는다
- 총관리자가 1명일 때 그 권한을 선관위원으로 바꾸는 시도는 거부된다

아래 항목은 이번 개발에 포함하지 않으며, 가정이 틀리면 명세를 고친 뒤 구현한다.

**범위 제외**

- 푸시·카카오톡 등 알림 발송 (승인 대기는 화면 배지로만 표시)

- 이메일 가입·비밀번호 로그인, 다중 선거 동시 운영

- 유권자수 변경 이력 보관 (v1.1에서 "유권자 명부 관리"는 범위에 포함되어 15절로 옮김)
- 단과대학 학생회 선거의 선거인명부와 투표용지 (별도 관리)

- 근무표 알림·발송, 위원별 "내 근무" 안내 (근무표는 조회 권한 판단에만 사용)
- 공지 이미지의 디자인 변경 (원본 SVG 재현만)

**가정 사항**

| 번호 | 가정 | 틀렸을 때 영향 |
| --- | --- | --- |
| A-1 | 공과대학3(법학관)은 야간 18:30\~22:30만 운영하고 주간에는 열지 않는다 | 해당 투표소 시점을 설정에서 추가하면 됨 |
| A-2 | 주간 투표소는 매일 같은 시간에 운영한다 | 날짜별 운영시간 설정이 필요 |
| A-3 | 선관위원 수는 30명 이하다 | 성능 요구 재검토 |
| A-4 | 현장 휴대폰은 인터넷에 연결된다 (LTE/5G 또는 Wi-Fi) | 오프라인 입력 후 동기화 기능 필요 |
| A-5 | 공지 이미지의 선거구 순서는 5절 순서와 같다 | 이미지 페이지 분할 재조정 |
| A-6 | 2026.11.25는 수요일이며 예시 이미지의 "(월)"은 가안이다 | 없음 (요일은 시스템이 계산) |
| A-7 | 코드 발급과 전달은 총관리자가 오프라인으로 한다 | 코드 전달 기능 추가 |
| A-8 | 이미 만든 Supabase 프로젝트의 리전이 서울(ap-northeast-2)이다 | 서울 리전으로 새 프로젝트를 만들어 옮겨야 함 (3차 착수 시 확인) |
| A-9 | 선거인명부 파일에 학번·이름·단과대학·학과 열이 있고, 학번만으로 한 사람이 특정된다 | 열 지정·식별 규칙 재검토 |
| A-10 | 한 학생은 정회원·준회원 중 한쪽 파일에만 있다 | 중복 학번 처리 규칙 추가 |
| A-11 | 명부 정정(누락자 추가 등)은 총관리자만 한다. 현장 위원은 명부에 없는 학생을 투표시킬 수 없다 | 현장 추가 절차 추가 |
| A-12 | 근무표 파일은 발주자가 개발 담당에게 보내 형식을 맞추고, 받기 전에는 15.5의 기본 열을 쓴다 | 업로드 열 매핑 조정 |

유권자수 확정값과 Supabase 계정은 발주자가 제공해야 하는 미확정 항목이다. v1.1에서 유권자수는 선거인명부로 대체되고 Supabase 계정은 준비됐다. 남은 제공 항목은 선거인명부 파일(정회원·준회원), 근무표 파일, 결과 공고일, 이의신청 기간이다.

## 15. 선거인명부 확인과 투표용지 불출 (v1.1 추가)

투표소 위원이 학번으로 선거인을 조회해 투표 여부를 체크하고 총학생회 투표용지를 불출한다. 체크 인원은 약 1시간마다 꼬리표 수와 맞춰 보며, 일치한 숫자만 투표율 공지에 쓴다. 이 절은 2026-11-05 요구사항 인터뷰(4라운드, Q1\~Q39) 결과다.

### 15.1 범위와 일정

| 항목 | 내용 |
| --- | --- |
| 다루는 선거 | 총학생회 선거 1종. 체크 1건 = 총학생회 투표용지 1장 불출. 단과대학 선거는 명부가 달라 범위 밖 |
| 투표 장소 | 학생은 본인 소속 단과대학 선거구의 투표소에서만 투표한다. 공과대학은 투표소 3곳 중 어디서나 |
| 운영 방식 | 온라인만 쓴다. 종이 선거인명부는 없다. 시스템 장애 때는 빈 기록 시트로 받고 복구 후 가져온다 (15.8) |
| 납품 | 3차. 11/14까지 로컬 모드 구현·검증 → 11/15 배포 반영 → 11/20 전후 가짜 명부로 리허설 → 체크 기록 초기화 → 11/22까지 실제 명부 업로드 |

### 15.2 선거인명부 등록

발주자가 가진 정회원(재학) 파일과 준회원(휴학) 파일을 총관리자가 배포된 사이트에서 직접 올린다. 개발 담당은 실제 명부를 받지 않는다. 파일 해석은 브라우저 안에서만 하고, 지정한 4개 열만 서버로 보낸다.

| 번호 | 기능 | 상세 | 우선순위 |
| --- | --- | --- | --- |
| FR-80 | 명부 업로드 | ① 종류 선택(정회원/준회원) → ② 파일 선택(.xlsx 또는 .csv, CSV는 UTF-8·엑셀 기본 인코딩 모두) → ③ 첫 줄(헤더)만 보여 주고 학번·이름·단과대학·학과 열을 지정 → ④ 단과대학 값 목록을 14개 선거구에 연결(예: "공대" → 공과대학), 선거권 없는 값은 "제외" → ⑤ 검증(빈 칸, 파일 안 중복 학번, 다른 종류 파일과 중복, 학번 길이 불일치, 연결 안 된 단과대 값). 오류가 있으면 올릴 수 없고 오류 목록(학번만)을 보여 줌 → ⑥ 1,000행씩 전송, 진행률 표시. 중간에 실패하면 그 업로드 전체를 되돌림 → ⑦ 결과는 선거구별 정회원·준회원 수만 표시 | 필수 |
| FR-81 | 명부 교체 | 같은 종류를 다시 올리면 그 종류 전체를 교체. 체크 기록이 1건이라도 있으면 교체 불가 (리허설 후에는 FR-97로 체크 기록을 먼저 초기화) | 필수 |
| FR-82 | 개별 정정 | 총관리자만 학번 단위로 추가·학적(정/준) 변경·선거구 변경. 사유 필수, 접근 로그 기록. 이미 투표한 사람의 삭제·선거구 변경은 불가 | 필수 |
| FR-83 | 기본 유권자수 자동 계산 | 명부가 있으면 선거구 기본 유권자수 = 그 선거구 정회원 수. 설정 화면의 손 입력칸은 읽기 전용으로 바뀜 | 필수 |
| FR-84 | 가짜 명부 생성 | 리허설·성능 검증용. 명부가 비어 있을 때만 23,000명(선거구별 비율은 목업 유권자수 기준, 준회원 약 5%)을 생성. 가짜 학번은 99로 시작해 실제 학번과 겹치지 않음 | 필수 |

학번은 앞뒤 공백을 지우고 숫자만 남겨 비교한다. 이름 검색은 지원하지 않는다.

### 15.3 학번 조회와 투표용지 불출

| 번호 | 기능 | 상세 | 우선순위 |
| --- | --- | --- | --- |
| FR-85 | 학번 조회 | 숫자 키패드로 학번 입력 → 조회. 서버가 근무 권한(15.5)을 확인한 뒤 결과를 돌려줌. 조회한 1명만 표시하고 목록은 없음 | 필수 |
| FR-86 | 투표용지 불출 | 결과 확인 → "신분증 확인함" 체크 → "투표용지 불출". 서버는 "아직 투표하지 않은 경우에만" 기록하는 단일 트랜잭션으로 처리. 두 투표소가 동시에 눌러도 1건만 성공하고 나머지는 "이미 투표함"을 받음. 완료 화면에 "이번 구간 n번째 불출" 표시 후 입력창 초기화 | 필수 |
| FR-87 | 결과별 표시 | 아래 표 | 필수 |
| FR-88 | 체크 취소 | 아직 일치 처리되지 않은 구간(마감 전 또는 대조 중)의 체크만 취소 가능. 체크한 위원 본인은 5분 안에 사유를 적고 취소, 그 밖에는 총관리자만. 취소는 기록을 지우지 않고 "취소" 기록을 하나 더 쌓으며, 그 학생은 다시 투표할 수 있는 상태가 됨. 일치 처리된 구간의 체크는 취소할 수 없고 총관리자 조정(FR-90)으로만 다룸 | 필수 |

| 조회 결과 | 화면 |
| --- | --- |
| 소속 선거구 · 미투표 | 이름, 학번(입력값), 학과, 정회원/준회원 배지, 신분증 확인 체크, 불출 버튼. 준회원(휴학생)이면 "휴학생 · 투표하면 재학생 명단(유권자)에 편입됩니다" 안내, 불출 완료 화면은 "재학생 명단 편입 · 투표 완료" |
| 소속 선거구 · 이미 투표 | 빨간 화면 "이미 투표함 · 11/23 13:42 · 경영대학 투표소" + 이름·학과. 불출 버튼 없음 |
| 다른 선거구 | "○○대학 선거구 학생입니다 · ○○대학 투표소로 안내". 이름·학과는 표시하지 않음 |
| 명부에 없음 | "선거인명부에 없습니다 · 투표할 수 없습니다". 현장 추가 기능 없음 (A-11) |

조회 결과는 30초 뒤, 또는 다음 조회·화면 이동 때 지운다. 응답은 브라우저 캐시에 남기지 않는다 (no-store). 위원 한 명이 1분에 30회를 넘게 조회하면 1분 동안 막고 접근 로그에 남긴다.

### 15.4 꼬리표 마감 (대조)

| 번호 | 기능 | 상세 | 우선순위 |
| --- | --- | --- | --- |
| FR-89 | 마감 | 근무 중인 위원 누구나 "꼬리표 마감"을 누름 → 누른 순간이 구간 경계로 고정되고 구간은 "대조 중"이 됨. 시스템은 이 구간의 체크 인원(불출 − 취소)과 그중 준회원 수를 보여 줌. 경계 이후의 체크는 다음 구간으로 들어가므로 투표는 멈추지 않음 → 위원이 꼬리표를 세어 입력 → **체크 인원과 같을 때만 저장**되어 "일치"가 됨. 투표소마다 대조 중인 구간은 하나만 둘 수 있음 | 필수 |
| FR-90 | 불일치 해소와 조정 | 다르면 저장을 거부하고 차이("꼬리표가 2장 많음")를 보여 줌. 해소 방법: ① 다시 세기 ② 체크 없이 용지를 준 학생의 학번으로 "이 구간 누락분" 체크 추가 ③ 용지를 주지 않았는데 체크된 건을 취소(FR-88). 그래도 맞출 수 없으면(꼬리표 분실 등) 총관리자만 "조정 완료": 인정 인원(기본값 체크 인원)과 사유를 입력하고, 조정값 = 인정 인원 − 체크 인원을 기록. 조정은 총원에만 반영하고 준회원 수는 체크 기준을 유지 | 필수 |
| FR-91 | 마감 지연 경고 | 운영 시간 중 직전 경계(개장 또는 직전 마감)로부터 70분이 지나도록 마감이 없거나, 대조 중 상태가 20분 넘게 이어지면 현황판과 총관리자 화면에 "마감 지연" 경고. 투표소 마감 시각(18:00, 야간 22:30)에는 반드시 마감해야 하고, 하지 않으면 그날 마감 미완료로 표시 | 필수 |

마감 기록에는 경계 시각, 체크 인원, 준회원 수, 꼬리표 수, 인정 인원, 조정값·사유, 처리자가 남고 수정·삭제할 수 없다. 야간 투표소는 18:30 개장 기준이므로 매시 30분 전후에 마감한다.

### 15.6 투표율 집계와 공지 연동

| 규칙 | 내용 |
| --- | --- |
| 실시간 체크 인원 | 현황판에만 표시. "실시간(대조 전)"이라고 이름표를 붙이고 공지·이미지·CSV에는 쓰지 않음 |
| 최근 대조 인원 | 투표소별 마지막 일치 마감의 인정 누적과 그 시각. 현황판에 실시간 인원과 나란히 표시 |
| 인정 누적 | 그 투표소의 선거 기간 전체 일치 마감 인정 인원의 합. 날짜가 바뀌어도 이어짐 (6절 누적 규칙과 같음) |
| 시점 값 | 투표소의 집계 시점 S의 값은 S−10분\~S+10분 안에 경계가 있는 일치 마감(여럿이면 가장 늦은 것)의 인정 누적과 준회원 누적. 시스템이 이 값으로 입력값(entry)을 자동 생성·갱신하고 입력자를 "꼬리표 대조(처리자 이름)"로 기록 |
| 대조 미완료 | 위 범위에 일치 마감이 없으면 그 칸은 "대조 미완료"(빨간색). 6절 이어쓰기 규칙은 현황판 표시에만 쓰고, 한 투표소라도 대조 미완료인 시점은 확정·공지 문구·공지 이미지 생성을 막음 |
| 확정 | 기존 확정 흐름(FR-30\~FR-33)을 그대로 쓴다. 다만 확정 대상 값은 대조로 생긴 값만 |
| 휴학생 반영 (편입) | 준회원이 불출되면 "재학생 명단 편입"으로 표시한다. 데이터는 옮기지 않고 한 사람 한 행에 편입 상태만 기록하며, 취소하면 자동으로 준회원 상태로 돌아간다. 휴학생 투표자수 = 인정 구간의 준회원 체크 수. 6절 식대로 분자와 분모에 함께 더해짐. 선거구 인원표는 "재학생 1,400 + 편입 휴학생 12 = 유권자 1,412" 형식으로 표시 |
| 기준 시각 표기 | 공지의 "12:00 기준"은 각 투표소 마감 경계 시각 기준이다. 11:55에 마감했다면 11:55\~12:00 체크는 다음 시점에 들어감 |

| 업로드 | 1,000행 단위 전송(요청당 약 150KB, Vercel 요청 한도 4.5MB 이내). 23,000명 업로드 2분 이내 |
| 응답 시간 | 학번 조회 1초, 불출 저장 2초 이내. 동시에 16개 투표소 × 2대. 학번 조회는 DB 왕복 2번(권한 검사와 선거인 조회를 동시에, 그다음 접근 로그)으로 처리하고, 투표소·선거구 이름은 서버 메모리에 60초 보관한다. 명부 확인 화면에 조회 응답 시간을 표시한다 |
| 로딩 표시 | 모든 화면에서 서버 요청이 0.25초를 넘으면 화면 가운데에 "불러오는 중"을 표시한다. 자동 갱신(폴링)은 표시하지 않는다 |
| 호출량 | 현황판 10초 폴링은 화면이 보일 때만 동작. 명부 화면은 폴링하지 않음. 선거 4일간 Vercel Hobby 월 호출 한도 안에 들도록 배포 전에 예상치를 확인 |
| 원자성 | 불출·취소·마감은 DB 트랜잭션 함수(Supabase는 Postgres 함수 RPC, 로컬은 SQLite 트랜잭션)로 처리 |
| 추가만 가능 | 체크 기록은 DB 트리거로 수정·삭제를 막음 (구간 번호를 한 번 채우는 것만 허용). 체크 기록 초기화·파기 함수만 예외 |
| 초기화 분리 | FR-72(전체 입력 초기화)는 명부·체크를 건드리지 않음 |
| FR-96 백업·복원 | 총관리자가 언제든 체크 기록 백업 CSV를 내려받음. S-11에 "마지막 백업 이후 마감 n건"을 표시해 마감마다 받도록 안내. 복원: 명부를 다시 올린 뒤 백업 CSV를 가져오면 HMAC 값으로 맞춰 투표 상태를 되살림 (같은 키 필요, 확인 문구 입력) |
| FR-97 체크 기록 초기화 | 리허설 후 체크·마감·조정 기록과 그로 생긴 입력값을 지우고 투표 상태를 모두 해제. 명부·근무표·접근 로그는 유지. 확인 문구 "체크기록초기화" |

### 15.11 수용 기준

- 가짜 명부 23,000명을 2분 안에 올리고, 선거구별 정회원 수가 기본 유권자수에 그대로 반영된다
- 휴대폰 2대가 같은 학번을 동시에 불출하면 1건만 성공하고, 다른 1대는 "이미 투표함"을 받는다
- 근무 시간이 아니거나 다른 투표소에 근무 중인 위원의 조회는 서버가 거부하고 접근 로그에 남는다
- 다른 선거구 학번을 조회하면 이름 없이 안내만 나온다. 명부에 없는 학번은 불출 버튼이 없다
- 꼬리표 수가 체크 인원과 다르면 저장되지 않는다. 총관리자 조정 후에는 대조표에 조정값과 사유가 보인다
- 12:00 시점 값은 각 투표소의 11:50\~12:10 일치 마감 인정 누적과 같다. 한 곳이라도 없으면 확정과 공지 생성이 막힌다
- 준회원 1명이 불출·대조되면 그 선거구 투표율의 분자와 분모가 함께 1씩 늘어난다
- Supabase 테이블을 그대로 내려받아도 이름·학과 평문과 학번 원문이 없다
- 전체 입력 초기화 후 명부·체크가 남고, 체크 기록 초기화 후 명부는 남고 투표 상태는 모두 해제된다
- 체크 기록 초기화 직후 백업 CSV로 복원하면 투표 상태가 초기화 전과 같다
- 파기 후 명부·체크가 0건이고, 접근 로그는 학번 정보 없이 남는다
- 서약하지 않은 위원은 명부 API를 쓸 수 없다
